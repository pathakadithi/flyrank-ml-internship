Content Opportunity Scoring for Search-Driven Content Review

A Decision-Support Approach Using Anonymized FlyRank Search Data

Abstract

This research asks whether observable search-performance signals can be used to prioritize pages for content review when review capacity is limited. The analysis uses anonymized FlyRank warehouse data and five historical features covering impressions, clicks, CTR, and search position. A Logistic Regression model was trained using the Week-4 baseline-defined opportunity label and evaluated using both a random stratified split and a client-grouped validation check. The model achieved an F1 score of 0.6141 under the random split and 0.6095 under client-grouped validation, with recall close to 1.0 in both checks. These results provide directional evidence that a learned scoring approach can approximate a rule-based content-opportunity policy, but they do not prove future recovery, causal refresh impact, or Google's ranking behavior.

Introduction / Problem Statement

Content teams can have more pages available for review than they can realistically inspect. The practical challenge is therefore to decide which pages deserve attention first.

This capstone focuses on the Refresh / Content Opportunity Scoring lane. The objective is to build a repeatable workflow that uses observable historical search-performance signals to prioritize pages for content review.

The Week-4 work provides a rule-based content-opportunity baseline. The Week-5 work then uses machine learning to learn the baseline-defined opportunity condition from historical performance features. A later client-grouped validation check is used to examine whether the observed performance remains similar when the model is evaluated on previously unseen clients.

Decision-support framing: The output is intended to help allocate limited content-review effort. It is not an automated content decision system.

Methodology

Baseline

The Week-4 baseline creates a content-opportunity score using observable historical search-performance signals such as search visibility, CTR, position, and recent performance.

Features

  • impressions_90d
  • clicks_90d
  • ctr
  • avg_position_90d
  • avg_position_last30

Label Definition

The target variable is baseline_action. A row receives a positive label when baseline_score > 0 and otherwise receives a negative label.

Therefore, the Week-5 model learns to reproduce the opportunity definition created by the Week-4 baseline. It should not be interpreted as an independent prediction of future traffic recovery or refresh success.

Model

The Week-5 model uses Logistic Regression to combine the historical features and estimate the baseline-defined opportunity class.

Validation

The initial Week-5 evaluation used an 80/20 random stratified train/test split with random_state=42.

A subsequent client-grouped validation check separated clients between training and testing to examine whether the observed result remained similar on previously unseen clients.

Leakage and Public-Safety Checks

The features are restricted to observable historical performance signals. The analysis does not use client names, domains, private queries, credentials, or future refresh outcomes as model features.

Because the target is derived from the Week-4 baseline rule, the model is interpreted as learning the baseline opportunity policy rather than predicting an independently observed future outcome.

Interpretation

The initial W05 random stratified validation produced an F1 score of 0.6141. The client-grouped validation produced an F1 score of 0.6095.

The difference between the two F1 scores is small, and accuracy also remained very similar. Recall remained extremely high in both validation designs, while precision was substantially lower.

This suggests that the model captures nearly all examples belonging to the baseline-defined positive class, while also producing a meaningful number of predictions that do not match the baseline label.

These metrics measure performance against the baseline-derived label. They do not demonstrate future traffic recovery, refresh impact, or Google's ranking algorithm.

Error Analysis

Under the W05 random split, the main model disagreement was false positives: 22,780 rows were predicted as opportunities but were not marked as opportunities by the W04 baseline rule.

These should be interpreted as disagreements with the baseline policy rather than proof that the pages are genuinely poor-performing.

Limitations & Honest Framing

  1. Baseline-derived target: The Week-5 model learns the W04 opportunity definition rather than an independently observed future outcome.
  2. Observational analysis: The results describe relationships and model performance within the available data and do not establish causal effects.
  3. Precision: High recall is accompanied by lower precision, so some candidates will not match the baseline-defined positive class.
  4. Validation: Random and client-grouped validation do not guarantee performance on every future client or future time period.
  5. Limited features: The model uses a small set of historical search-performance signals.
  6. Human review: A high-scoring page should be treated as a candidate for review, not an automatic refresh decision.
  7. No Google-algorithm claim: This research does not attempt to identify Google's internal ranking factors.
Strongest supported conclusion: The learned model provides a repeatable way to approximate the Week-4 content-opportunity policy using observable historical signals, with broadly similar measured performance under a client-grouped validation check.

Ranked Recommendations

Priority 1 — Model Decline Risk

Action: Review pages receiving a strong model opportunity signal.

Review: Recent performance, search intent alignment, content freshness, and usefulness.

Priority 2 — Visible Model Opportunity

Action: Review pages with meaningful search visibility that also receive an opportunity signal.

Review: Content quality, relevance, structure, and usefulness.

Priority 3 — CTR Review Candidate

Action: Review pages with meaningful impressions but relatively weak CTR.

Review: Title, description, search-intent alignment, and value communication.

Priority 4 — Engagement Review Candidate

Action: Review pages with meaningful sessions but weaker engagement signals.

Review: Content structure, readability, relevance, and user intent satisfaction.

Recommended Workflow

  1. Generate opportunity scores.
  2. Rank candidate pages by score.
  3. Assign a reason code.
  4. Apply the corresponding review action.
  5. Have a human reviewer inspect the page.
  6. Monitor subsequent performance rather than assuming improvement.
